# Azure DevOps: project-specific authoring contract

Use this file only when this project actually uses Azure DevOps. Connections and primary-provider choice belong in `config.json`; do not invent an organization, project, PBI or Task ID here.

## Description format and language

No project-specific override is approved merely because this scaffold exists. Before the first Description edit, read actual project rules and current work items, then record the owner's chosen headings, language order, evidence/link conventions and any approved example IDs here. Preserve existing approved conventions. If unknown, draft locally using the skill's `rules/task-descriptions.md` and identify the unresolved convention.

Wh-Questions check content rather than impose headings: why this task matters, what it produces, how and where it is verified, who uses it for which decision, and relevant known dates. Keep expected work separate from actual results and limitations. Use English + the native language in one field only if the owner/project requires it; keep both meanings and numbers identical.

## Write scope and verification

Normal docs sync is read-only toward ADO. A specifically requested Description update changes only the authorized field/items. Follow the skill's Description workflow: live read, concrete draft, concurrency protection, write, readback and UI inspection when available. Preserve existing attachments, links and unique evidence; report anything not visually checked. Do not copy credentials or private work-item payloads into this file.
