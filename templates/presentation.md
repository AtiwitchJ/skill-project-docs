# Phase presentations

Read before creating or changing `phase-N/presentation.html`. A presentation is what decision makers actually see: a wrong number, a table overflowing on mobile, or a raw backtick there is a defect that reached the customer, and the user usually finds it before we do.

## 1. Before writing

- Name the audience (decision makers, team, project lead) and the decision they make after watching.
- Write each slide's point as a full sentence (action title) before choosing a layout.
- Aim for 6–8 slides per phase unless a recorded reason says otherwise.
- Before writing any number, name its owner file (`owner-map.md`).
- `phase-N/tasks.md` must exist first. New presentation: `sync_presentation.py <N> --new` (from `presentation-template.html`).
- Read `rules/presentation-charts.md` to select evidence encodings and configure step grouping. Each phase gets a derived flow in both `tasks.md` and `presentation.html`; task headers own state, not a second hand-written status list.

## 2. Standard slide set

Adjust count and order per phase, but slides 1, 2, 4, 5 and 6 are required.

1. **Cover:** phase, period, status, last-updated date, and a one-line status counted from `phase-N/tasks.md` (AUTO block).
2. **Goal and route:** per the project's source plan (`.project-docs/rules.md`), plus the AUTO phase flow with all active/blocked steps and verified task counts.
3. **Task status:** one row per task with labels เสร็จ / กำลังทำ / บล็อก, plus evidence or what's pending (AUTO block).
4. **Verified results:** numbers with the result file name and run date, pulled from JSON by script, or "ยังไม่มีผล". Comparisons across Options use a chart (SVG generated by script), not paragraphs.
5. **Limitations:** synthetic or real data, number of runs, who judged (an LLM judge is not a human check).
6. **Blockers and owners:** who must do what to unblock, with Issue IDs.
7. **Next steps and links:** TASKS, DELIVERABLE, roadmap; one line per next item.

## 3. HTML rules

- One self-contained HTML file. One slide = `<section class="slide">` with a slide number and an `<h2>`; the first slide is the title slide.
- The current template has reading/presentation modes, slide index and counter, keyboard previous/next/Home/End/Escape, full screen, print/PDF styles and inspectable chart data. Presentation mode can select one evidence chart at a time; reading and print show all charts. Keep those controls accessible; slide position is separate from task completion.
- Use generated SVGs for source-backed charts. Every chart answers a named question and explains its encoding, unit, limits and source. Custom charts follow `rules/presentation-charts.md`; never imply unsupported renderer types are built in.
- Folio = slide number + short title. No eyebrows, decorative numbers, gradients, or monospace without a purpose.
- Don't repeat the same card row across the deck; pick a table, flow, diagram or one highlighted statement per content.
- Numbers and status must match TASKS and the raw result files. No evidence → "ยังไม่มีผล". Never guess.
- When status changes, delete the old text (e.g. "Planned", stale dates) instead of appending.
- No raw backticks on the page; use `<code>`.
- Relative links to files that exist; never `file:///`.
- No overclaims such as "สำเร็จ 100%" while a client or test round is still open.
- Mermaid: `<div class="diagram"><script type="text/x-mermaid">…</script></div>` with a source fallback if the library fails to load.
- Readable on small and large screens, clear contrast and focus, respects `prefers-reduced-motion`.
- Paired `.md`/`.html` match in the same pass. If phase status changed, update `roadmap.md`/`.html` too.

## 4. QA (required before reporting done)

### By script

```bash
python3 ~/.agents/skills/project-docs/scripts/sync_presentation.py <N> --check   # AUTO blocks match TASKS
python3 ~/.agents/skills/project-docs/scripts/check_docs.py --phase <N>         # markup, links, slide numbers, TODO, backticks
python3 ~/.agents/skills/project-docs/scripts/qa_presentation.py <N> --shots <scratchpad>/shots   # real render at 1280px and 390px
```

| Check | Script | Fails when |
|---|---|---|
| Cover and status table match TASKS | `sync_presentation.py --check` | AUTO block differs |
| MD/HTML flow, step grouping and SVG assets match owner files | `sync_presentation.py --check` and gate | Missing/duplicate task refs, stale blocks or hand-edited assets |
| Charts match JSON source and custom generator | `sync_presentation.py --check` and gate | Invalid values, stale checksums or missing source/generator |
| Relative links to existing files, no `file:///` | `check_docs.py` | Broken link |
| Consecutive slide numbers, unique ids, `<h2>` present | `check_docs.py` | Gap or duplicate id |
| No leftover `TODO`, no raw backticks | `check_docs.py` | Found |
| No horizontal page scroll on desktop and mobile | `qa_presentation.py` | `page scrolls horizontally` |
| Status-pill count equals task count | `qa_presentation.py` | Counts differ |
| Mermaid renders or shows source | `qa_presentation.py` | Empty diagram |

Tables scrolling inside their own box (`.tbl` / `.table-wrap` with `overflow-x:auto`) are fine, but for a newly added table try dropping columns first; on mobile people rarely notice it scrolls.

If `qa_presentation.py` exits 2 (no Playwright), serve with `python3 -m http.server`, check in an available browser, and say how it was checked.

### By eye (scripts can't check narrative)

Open the `--shots` images and check at least:
- Each action title is still true for the current status (sync never touches narrative; "ทุก Task รอเริ่ม" is wrong once any task starts).
- "Planned", "กำลังทำ" and dates outside AUTO blocks are still correct.
- No overclaims.
- Every number outside AUTO blocks names its source file and matches it.
- Limitations (synthetic data, run count, LLM judge ≠ human) are still shown.
- The chosen chart actually answers the question; axis/zero baseline, color scale, paired observations and missing values are not misleading.
- Navigation works in both modes; source tables open; chart scrolling stays inside its container on mobile; print shows every slide even when presentation mode hides others.

### Report

Separate script checks, eye checks, and what wasn't checked, e.g.:

> Script: sync, gate, render 1280/390 all pass · desktop screenshot looked at by eye · mobile screenshot not looked at · Safari not tested

Never write just "checked" when only scripts ran; scripts can't check narrative.

## Test reports and layout scale

Follow `rules/test-reporting.md` for automatic paired test reports and observed failure-stage workflows. Native unittest captures lifecycle stages; JUnit-only imports do not infer them. Attach via `run_tests.py --phase N`; Task acceptance remains manual and evidence-based. Check readable text, keyboard scrolling, vertical mobile steps, empty/error states and large inventories at phone, tablet and desktop widths. Missing metrics remain explicit.
